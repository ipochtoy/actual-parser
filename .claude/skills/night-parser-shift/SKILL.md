# Проверка ночного Parser Pro

Ночью работает машина состояний AutoBuy, а не отдельная фоновая AI-сессия.
Старый `com.pochtoy.night-fedya` снят: он обходил аренду браузера и мог мешать
уже работающему обходу. При обновлении выполнить `launchctl bootout` для этого
точного сервиса и убрать его plist из `~/Library/LaunchAgents` в архив.

1. Прочитать `~/Desktop/AutoBuy/docs/STORE_WALK_ROUND.md`, раздел единого ночного
   координатора, и живое состояние `agent/tmp/night-cabinet-coordinator/<дата>.json`.
2. Ночной запуск и продолжение — только `node agent/night-cabinet-coordinator.mjs
   --wake=watchdog` из AutoBuy. Команда сама проверяет время и владельца браузера.
   Не вызывать напрямую `startSequentialPipeline`, `runPipelineStage` или менять
   `nightCabinetLease`, очередь кадров и отметки завершения через storage.
3. Для чтения живого браузера использовать общую `AutoBuy/agent/lib/cdp.mjs`:
   она выбирает рабочий вход Chrome. Не фиксировать старый порт 9222.
4. Успех требует конкретного `pipelineRun.id`: completed, все 3 iHerb + 1 eBay +
   2 Amazon, пустые failures/missing, stage done, пустая очередь без блокировки,
   совпадающий `lastSheetsUploadRunId`, подтверждённая синхронизация книги и уборка.
   `active=false` или одна отметка времени выгрузки не доказывают успешный обход.
5. При ремонте сохранять чужие изменения. Reload допускается только после свежей
   проверки idle у бота и отсутствия активного парсинга/рассылки. Вход в кабинеты —
   штатной дверью; не выполнять оплату, отмены и ручное переключение стадий.

Внешний сторож `watchdog/parser-watchdog.mjs --dry-run` только читает.
Его штатный запуск может разбудить координатор, но не создаёт второй обход.
